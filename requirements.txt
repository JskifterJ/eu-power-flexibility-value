# C1 (config, Energy-Charts client, cache, manifest):
requests>=2.32
PyYAML>=6.0
pandas>=2.2
numpy>=1.26
pytest>=8.0

# C2 (stitching loader, data contracts, hourly aggregation, price figures):
matplotlib>=3.8

# C3 (walk-forward harness, naive model, leakage guard): no new dependencies —
# pandas/numpy/pytest already cover it.

# C4 (LEAR: per-hour LASSO, in-fold asinh/standardisation, in-fold AIC/BIC/CV
# penalty selection). The floor is 1.7 because LassoCV's alpha-path argument was
# renamed there (`n_alphas` -> an int `alphas`), and forecast/lear.py uses the
# current spelling.
scikit-learn>=1.7

# C5 (battery dispatch LP + MILP). scipy is already present transitively via
# scikit-learn, but C5 depends on it directly so it is declared directly. HiGHS
# ships inside scipy, so there is no separate solver install and no licence:
# `scipy.optimize.linprog(method="highs")` for the LP and `scipy.optimize.milp`
# for the forbid_simultaneous variant. The floor is 1.11 because `milp` and the
# `Bounds`/`LinearConstraint` objects it takes settled into their current form
# there.
scipy>=1.11

# C7 (ENTSO-E client, exogenous loader, manifest + contracts): no new
# dependencies. The Transparency Platform returns XML, parsed with the standard
# library's xml.etree.ElementTree — no lxml, and deliberately no `entsoe-py`:
# the whole point of data/entsoe.py is the explicit refusal behaviour CLAUDE.md
# requires (an Acknowledgement is a FLAG, nothing is retried that should not be,
# nothing unvalidated reaches the cache, the token never reaches disk), which a
# convenience wrapper would hide.

# C8 (exogenous features into LEAR, Tier A, + the RES-forecast degradation
# sensitivity): no new dependencies. The exogenous columns are a join and a
# vintage offset on top of C7's loader, and the model is C4's committed LEAR.

# C9 (the gradient-boosted model: one fixed LightGBM config, in-fold early
# stopping, Tier A only). The floor is 4.3 because `lgb.early_stopping` settled
# into the callback form forecast/gbm.py uses there, and because 4.x is where
# `deterministic=True` became reliable enough to assert bit-reproducibility on
# (tests/test_c9_gbm.py::test_the_fit_is_bit_reproducible). PLAN.md forbids a
# hyperparameter search across cycles, so the committed config lives in
# `forecast.gbm.GbmSpec`, is fingerprinted into every result row, and is pinned
# to literals by a test — a later cycle cannot tune a knob without editing a
# test, which CLAUDE.md makes a flag-and-stop event.
lightgbm>=4.3

# C10 (scale the harness to all nine zones + the append-only results store): no
# new dependencies. The store is csv/json/hashlib from the standard library on
# top of pandas, deliberately — a results table that a later cycle must be able
# to read, diff and verify by hand should not need a database or a serialisation
# library to open. Note that every row records the installed versions of
# numpy/pandas/scikit-learn/scipy/lightgbm as a `library_fingerprint`: the
# model config fingerprints pin the values this project sets, and a library
# default moving underneath them would otherwise change a result invisibly.

# C11 (the battery LP across all nine zones x every committed curve, with the
# per-day capture ratios persisted): no new dependencies. The dispatch stack is
# C5's — scipy's bundled HiGHS for the LP — and C11 adds no solver, no bootstrap
# library and no plotting. scipy.stats is used only in the PROGRESS.md analysis
# of the cross-zone table, not in the committed code path; C12's block bootstrap
# is numpy resampling and will not need one either.

# C12 (the metrics layer + block-bootstrap CIs over daily blocks): no new
# dependencies, as the C11 note predicted. The two new metrics are pandas
# groupby plus `Series.rank` (a Spearman is Pearson on average ranks, which is
# the definition — deliberately not `scipy.stats.spearmanr`, whose p-value this
# project has no use for at a per-day n of 24, and whose per-call overhead would
# dominate a 10 000-replicate loop). The bootstrap is `numpy.random.default_rng`
# plus one matrix product: a circular moving-block resample is drawn once as a
# (n_replicates x n_days) count matrix, and every day-additive statistic is then
# `counts @ column`, so no resampling library is needed and the replicate
# statistic is computed by the same formula as the point estimate. No plotting
# and no solver: C12 re-dispatches nothing.

# C13 (the regime analysis: per-year tables 2020-2024, the crisis year reported
# separately, the cutover flag, negative-hour counts): no new dependency, and
# nothing in the existing set moved. The cycle is 36 walk-forward runs of C4's
# committed LEAR, 36 runs of C5/C6's dispatch LP, and C12's metric and bootstrap
# layer imported rather than re-derived — so a 2022 capture ratio is produced by
# the same lines of Python as the 2024 one already in results.csv. The
# library_fingerprint is unchanged from C10/C11/C12 (856fb19ac0c4eecd), which is
# what makes C10-C13 rows directly comparable; a new version of numpy, pandas,
# scikit-learn, scipy or lightgbm here would have made the five per-year columns
# incomparable to each other as well as to the published 2024 ones.
